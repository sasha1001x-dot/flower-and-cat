# 花猫第一版：产品范围与验收标准

版本：0.1 工作基线，2026-10-21。已确认：鲜花与盆栽都覆盖，先做常见品种。

## 服务谁，解决什么

为养猫、养狗和猫狗同养家庭提供有来源的植物风险参考、养护资料和个人实践交流。首先帮助用户在买花前、摆放前或发现宠物接触后，找到植物身份与猫狗风险信息。

核心流程：登录花猫 → 搜索植物或拍照获取候选 → 核对学名和档案层级 → 分别查看猫狗风险与预防方法 → 收藏或分享经验。照片候选不是确诊，未收录或身份不明显示未知。高危疑似接触不要等待识别完成才联系兽医。

用户选择养宠身份不会将对另一种动物的风险隐藏或删除。称号为用户自述，不代表认证。

## 暂缓事项

付费会员、支付、积分、排行榜、商城、广告、私信、即时诊疗、自动推荐药物、按点赞自动修改毒性结论。经验首版建议仅文字，照片经验另行规划审核和存储。

## 首批资料怎样选择

首批30个分类档案是编辑工作清单，不是“全国最热门30种”的统计排名，也不等于30个物种。包含原有百合、菊花的总览与细分类档案，并补充郁金香、康乃馨、绣球、水仙、风信子、芦荟、龟背竹、虎尾兰、蝴蝶兰、波士顿蕨、袖珍椰子、瓜栗、长寿花、杜鹃等场景。

不追求堆条目数量。只有属级毒性资料时保留总览或明确“属级参考”；不能为每个花色编造专属毒性结论。商业名称仍需辨别。

## 资料何时才算可以公开上线

每个正式发布档案应有：

1. 明确的学名、分类层级、俗名歧义与来源适用范围。
2. 猫和犬各自的证据；未知有说明，不互相推断。
3. 来源 URL、实际核对日期、分类和养护依据。
4. 可追溯的兽医内容复核与园艺/分类复核记录，不冒签审阅人。
5. 有权使用、物种可核对的实拍照片及作者、许可、来源记录；属级总览要注明示例照片代表什么。
6. 没有未处理的安全结论冲突、错误学名或与来源不符的剂量承诺。
7. 相关检索、别名及未知状态测试通过。

`npm run audit:data` 展示资料缺口；`npm run check:release-data` 在存在复核、照片或已登记的资料缺口时明确阻止把资料标成发布就绪。机器检查只能检查结构，不能替代专业判断。

## 分工

Codex：编程、公开来源核对、原创摘要、资料清单、缺口记录、同步预览、测试和交付说明。

运营者：决定产品方向，后续办理运营账号和许可，安排可信的专业审阅、提供或取得可用照片。当前不要求运营者写代码或操作命令。

专业审阅人：确认植物身份与证据推断是否合适，记录审阅范围、姓名/可验证身份、日期与结论。未完成时始终保持“待复核”。
