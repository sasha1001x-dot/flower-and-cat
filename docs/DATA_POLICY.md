# 植物档案的数据规范

## 身份和结论分别记录

档案 `id` 是本项目标识，不冒充外部分类数据库的稳定标识。`latin`、`genus`、`family`、`rank` 表示该档案的分类粒度；`parentId` 用于已明确的上级档案，`related` 只表示比较入口，不是分类继承关系。

`rank` 可以是物种、属级总览、园艺杂交群、杂交分类单元、栽培品种。园艺商品名不作为科学分类单元；`ambiguities.js` 独立保存这些名称的辨别说明。`aliases` 只放经过核对、适合用于候选检索的名称。已列入歧义表的词优先按歧义处理。

`evidenceTaxon` 是来源实际讨论的分类单元，不能把属级来源伪装成品种独立试验证据。`evidenceScope` 解释适用范围。没有独立证据不等于无毒，也不能凭亲缘关系把所有菊科植物认定为同一种风险。

`cat` 和 `dog` 分别记录，不互相推断。`unknown` 表示该动物的依据尚未补齐，不是中等风险，也不是无毒。风险标签是产品展示分组，不是剂量、预后或临床分级。

## 来源与状态

每条 `sources` 包含标题、URL、类型（毒性 / 分类特征 / 养护）、访问核对日期。来源只有链接和原创摘要，不复制原始数据库全文或照片。引用不自动授予原文再分发许可。

`reviewStatus` 目前统一明确标记为网页核对、未经兽医复核。没有真实审阅人和审阅记录，不得改为“专业审核”。`reviewedAt` 不是实时更新保证。

`careStatus` 必须区分有来源的一般参考和仍待补齐的说明。属级园艺指南不能声称适用于所有栽培品种、地区和环境；不要把英国的日历月份直接变成全国统一的养护时间。

## 当前覆盖和缺口

首批扩展为 30 个分类档案，并不等于 30 个物种。范围和验收见 FIRST_RELEASE.md，逐条缺口见 PLANT_READINESS.md。无照片鉴定模型、无人工鉴定服务、没有完整品种注册目录。商业菊花品种的独立毒性剂量、商业杂交非洲菊的独立依据尚未收录，不虚构结论。

身份已知的高危百合参考 FDA 的明确清单；“去花粉”“无粉”不能据此成为安全标签。栽培菊参考 ASPCA 菊属资料，但页面不得表示已独立验证某个商品品种的毒性。犬对萱草的结论暂列未知。现有档案已附养护来源，但还没有专业园艺签审；来源范围和未复核状态直接展示在页面。

## 新增或修订流程

1. 确认学名和层级；发生同名、异名或商品名歧义时先新增辨别提示。
2. 分别查证猫和犬的毒性，记录来源的实际适用范围，不自行编造剂量。
3. 将分类和园艺依据分别附在来源中；不以人可食用推断宠物可食用。
4. 填写边界、误食预防、相关比较入口和复核状态。
5. 运行 `npm test`，再 `npm run sync:preview`，检查微信和浏览器的搜索、档案、来源及未知状态。
6. 面向公众提供医疗相关结论前，安排可追溯的专业审阅。发现资料冲突时保留冲突说明，先撤销无法支持的安全结论。

## 照片判断边界

模型分数不是分类身份真实性的保证，更不是宠物安全概率；不设置一个分数阈值就将其变成已确认物种。所有识别结果都标注身份待确认，名称有歧义显示比较候选，未知名称显示未收录。用户仍需核对植物标签、学名或寻求专业鉴定。高危疑似误食应立即联系兽医，不能等待模型或人工鉴定完成。
